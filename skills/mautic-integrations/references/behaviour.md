## A. Discovery and registration

1. A legacy Integration class is discovered by scanning `plugins/<Bundle>/Integration/*Integration.php` of plugins installed in the `plugins` table, plus `app/bundles/*/Integration/*Integration.php` for core. The name is the file basename minus `Integration.php`. [code: app/bundles/PluginBundle/Helper/IntegrationHelper.php:94-110,160-173 @7.x]
2. The legacy Integration object is the container service `mautic.integration.<lowercased name>`. If it is missing, the Integration is silently unavailable. [code: app/bundles/PluginBundle/Helper/IntegrationHelper.php:117-121,259-264 @7.x]
3. First discovery persists a `plugin_integration_settings` row immediately: unpublished, `supported_features` set to all the class's features, `api_keys = []`. This also happens on GET requests. [code: app/bundles/PluginBundle/Helper/IntegrationHelper.php:112-132,175-195,210-213 @7.x]
4. `getIntegrationObjects()` sorts by `getPriority()` ascending (default 9999 for legacy, 1 for `BasicIntegration`) or alphabetically. `$withFeatures` filters on stored `supported_features`, and `$publishedOnly` drops unpublished Integrations. [code: app/bundles/PluginBundle/Helper/IntegrationHelper.php:217-296 @7.x] [code: app/bundles/PluginBundle/Integration/AbstractIntegration.php:180-183 @7.x] [code: app/bundles/IntegrationsBundle/Integration/BasicIntegration.php:36-39 @7.x]
5. Modern auto-tagging: `IntegrationInterface` → `mautic.integration`, `BasicInterface` → `mautic.basic_integration`, `ConfigFormInterface` → `mautic.config_integration`, `BuilderInterface` → `mautic.builder_integration`. [code: app/bundles/IntegrationsBundle/DependencyInjection/IntegrationsExtension.php:26-33 @7.x]
6. `mautic.sync_integration` and `mautic.authentication_integration` must be tagged manually. A sync Integration that is not tagged throws `IntegrationNotFoundException` "has not been tagged with mautic.sync_integration". [code: app/bundles/IntegrationsBundle/Helper/SyncIntegrationsHelper.php:34,57-59 @7.x] [code: app/bundles/IntegrationsBundle/Helper/AuthIntegrationsHelper.php:24 @7.x]
7. A modern Integration needs its settings row. Without it, `getIntegrationConfiguration()` throws "doesn't exist in the database", and `getEnabledIntegrations()` skips it as not yet installed. [code: app/bundles/IntegrationsBundle/Helper/IntegrationsHelper.php:87-98 @7.x] [code: app/bundles/IntegrationsBundle/Helper/SyncIntegrationsHelper.php:74-84 @7.x]
8. `BuilderIntegrationsHelper::getBuilder($feature)` returns the first published builder that supports the feature (`email` or `page`). [code: app/bundles/IntegrationsBundle/Helper/BuilderIntegrationsHelper.php:37-49 @7.x] [devdocs: https://devdocs.mautic.org/en/7.2/plugin_integrations/integrations_builder.html]
9. The `/s/plugins` grid lists non-missing plugins. Plugins without an Integration link to the info modal, and Integrations link to the config modal. Items are natural-sorted, and the plugin filter is kept in session `mautic.integrations.filter`. [code: app/bundles/PluginBundle/Controller/PluginController.php:39-134 @7.x]
10. The icon is `Assets/img/icon.png` for a bundle, or `Assets/img/<lowercase name>.png` for a legacy Integration, with the fallback `PluginBundle/Assets/img/generic.png`. Modern Integrations return `getIcon()`. [code: app/bundles/PluginBundle/Helper/IntegrationHelper.php:595-617 @7.x] [code: app/bundles/PluginBundle/Integration/AbstractIntegration.php:226-242 @7.x]

## B. Settings, encryption and the config modal

11. Settings columns: `is_published`, `supported_features`, `api_keys` (encrypted, not nullable), and `feature_settings`. Legacy `feature_settings` keys are `leadFields`, `companyFields`, `update_mautic`, `update_mautic_company` and `objects`. Modern keys are `sync.objects`, `sync.fieldMappings[object][field] = {mappedField, syncDirection}` and `integration`. [code: app/bundles/PluginBundle/Entity/Integration.php:49-85 @7.x]
12. `Integration::isChanged()` tracks name, published state, features and settings, but not `apiKeys`. [code: app/bundles/PluginBundle/Entity/Integration.php:124-214 @7.x]
13. Legacy form (`DetailsType`): `isPublished` has the `CanPublish` constraint. `apiKeys` comes from `getRequiredKeyFields()` minus `hide_keys`. An Authorize button appears when `requires_authorization`. Features default to all for a never-saved Integration. `PLUGIN_ON_INTEGRATION_FORM_BUILD` is dispatched last. [code: app/bundles/PluginBundle/Form/Type/DetailsType.php:24-176 @7.x]
14. Secret keys render as password fields with placeholder `**************`. A required key is enforced only when submitted with `isPublished=1`. A secret that is already stored is not required. [code: app/bundles/PluginBundle/Form/Type/KeysType.php:18-64 @7.x]
15. On legacy POST, a blank secret keeps the stored value. A changed client id or secret discards `getAuthTokenKey()` and the refresh-token keys. [code: app/bundles/PluginBundle/Controller/PluginController.php:196-210,443-462 @7.x]
16. Legacy keys are encrypted per value. On read, a value that fails with the primary cipher is retried with the secondary cipher, then re-encrypted and flushed. Decrypted keys are memoised per ciphertext. `PLUGIN_ON_INTEGRATION_KEYS_DECRYPT` can replace them. [code: app/bundles/PluginBundle/Integration/AbstractIntegration.php:421-479 @7.x]
17. `cleanUpFields()` drops mappings to fields that no longer exist and defaults missing `update_mautic[<field>]` to `1`. It always keeps the pseudo fields `mauticContactId`, `mauticContactTimelineLink` and `mauticContactIsContactableByEmail`. Missing required mappings fail validation only for a published Integration. [code: app/bundles/PluginBundle/Integration/AbstractIntegration.php:1386-1480 @7.x] [code: app/bundles/PluginBundle/Controller/PluginController.php:212-249 @7.x]
18. An "authorize" POST (`in_auth`) restores the previous feature settings, saves even if invalid, and returns JSON `{integration, authUrl, authorize: 1}`. `PLUGIN_ON_INTEGRATION_AUTH_REDIRECT` may rewrite the URL. [code: app/bundles/PluginBundle/Controller/PluginController.php:250-293 @7.x]
19. `PLUGIN_ON_INTEGRATION_CONFIG_SAVE` is dispatched only when listeners exist. An invalid form on a previously unpublished Integration is forced unpublished first. [code: app/bundles/PluginBundle/Controller/PluginController.php:255-270 @7.x]
20. `CanPublishValidator` dispatches `PLUGIN_IS_PUBLISHED_STATE_CHANGING` only when the value is exactly int `1`. A listener calling `setCanPublish(false)` adds a violation. [code: app/bundles/PluginBundle/Form/Constraint/CanPublishValidator.php:21-36 @7.x]
21. `appendToForm($builder, $data, $area)` is called for the areas `keys`, `features` and `integration`. The `integration` area is the per-action config in campaign, form and point actions. [code: app/bundles/PluginBundle/Form/Type/KeysType.php:63 @7.x] [code: app/bundles/PluginBundle/Form/Type/FeatureSettingsType.php:37 @7.x] [code: app/bundles/PluginBundle/Form/Type/IntegrationConfigType.php:17-19 @7.x]
22. Legacy field mapping lists required fields first (a field is required when `required` is set or its label is `Email`) and paginates. Each field carries hidden `i_N`/`m_N` pairs. The `update_mautic` toggle (1 = default) sets direction. The `plugin:matchFields` AJAX action persists one mapping immediately, and `-1` or an empty value removes it. [code: app/bundles/PluginBundle/Form/Type/FieldsTypeTrait.php:21-231 @7.x] [code: app/bundles/PluginBundle/Controller/AjaxController.php:231-279 @7.x]
23. Modern modal: requires `plugin:plugins:manage` and dispatches `INTEGRATION_CONFIG_FORM_LOAD`. GET clears session `{integration}-fields`. POST runs in this order: `INTEGRATION_API_KEYS_BEFORE_SAVE`, merge and validate the session field mappings (sync Integrations only), `INTEGRATION_CONFIG_BEFORE_SAVE`, re-show the form if it is invalid and (published or authorizing), otherwise save, then `INTEGRATION_CONFIG_AFTER_SAVE`. Save on a `ConfigFormAuthorizeButtonInterface` Integration returns `authUrl` after `INTEGRATION_CONFIG_ON_GENERATE_AUTH_URL`. [code: app/bundles/IntegrationsBundle/Controller/ConfigController.php:48-262 @7.x]
24. Modern form content: `isPublished`. `apiKeys` uses `getAuthConfigFormName()` and appears only with `ConfigFormAuthInterface`. `supportedFeatures` (`sync`, `push_activity`) appears only with `ConfigFormFeaturesInterface`. `featureSettings.integration` and `featureSettings.sync` (objects + `fieldMappings`) follow. [code: app/bundles/IntegrationsBundle/Form/Type/IntegrationConfigType.php:32-88 @7.x] [code: app/bundles/IntegrationsBundle/Form/Type/IntegrationSyncSettingsType.php:23-81 @7.x]
25. Auth-tab values are encrypted. Feature-settings values are not. [devdocs: https://devdocs.mautic.org/en/7.2/plugin_integrations/integrations_configuration.html#configformfeaturesettingsinterface] [code: app/bundles/IntegrationsBundle/Helper/IntegrationsHelper.php:64-82 @7.x]
26. Modern field-mapping AJAX pages show 15 fields and filter case-insensitively on label. Edits stay in session until Save, Apply or Cancel. An unsupported direction falls back to bidirectional, then to-integration, then to-Mautic. [code: app/bundles/IntegrationsBundle/Helper/FieldFilterHelper.php:24-80 @7.x] [code: app/bundles/IntegrationsBundle/Helper/FieldMergerHelper.php:28-163 @7.x] [code: app/bundles/IntegrationsBundle/Form/Type/IntegrationSyncSettingsObjectFieldType.php:49-80 @7.x]
27. Required-mapping validation on modern save runs only when the Integration is published with `sync` enabled. It flags unmapped integration-required fields and Mautic-required fields (required plus unique identifiers for Contacts) that nothing maps to. [code: app/bundles/IntegrationsBundle/Helper/FieldValidationHelper.php:29-157 @7.x]

## C. Legacy push/pull and `integration_entity`

28. `integration_entity` columns: `integration` (name), `integration_entity` (remote type, e.g. `Lead`, `Contact`, `Account`), `integration_entity_id`, `internal_entity` (`lead`, `company` or a marker), `internal_entity_id`, `last_sync_date` and `internal` (array). There are no foreign keys to `leads`. [code: app/bundles/PluginBundle/Entity/IntegrationEntity.php:64-105 @7.x]
29. Contact or Company delete removes rows `LIKE 'lead%'` / `'company%'` for that id. On `LEAD_POST_SAVE`, if any published Integration with keys supports `push_lead`, `lead-error` rows reset to `lead`, and rows without a remote id are deleted. [code: app/bundles/PluginBundle/EventListener/LeadSubscriber.php:33-77 @7.x] [code: app/bundles/PluginBundle/Entity/IntegrationEntityRepository.php:499-535 @7.x]
30. A remote deletion rewrites `internal_entity` to `<type>-deleted` and does not delete the row. [code: app/bundles/PluginBundle/Entity/IntegrationEntityRepository.php:482-497 @7.x]
31. `findLeadsToUpdate()` selects mapped rows whose Mautic record changed after `last_sync_date` and that have a remote id and an email (company: a name). `findLeadsToCreate()` selects identified Contacts with email and no row `LIKE 'lead%'` for that Integration. [code: app/bundles/PluginBundle/Entity/IntegrationEntityRepository.php:166-305,310-406 @7.x]
32. The Contact "Integrations" tab excludes rows whose `internal` contains `error`, rows without a remote id and, when unfiltered, unpublished Integrations. [code: app/bundles/PluginBundle/Entity/IntegrationEntityRepository.php:421-480 @7.x]
33. `createIntegrationEntity()` stamps dates with `MAUTIC_DATE_MODIFIED_OVERRIDE` (the command start time) when defined, which prevents a pull/push loop. [code: app/bundles/PluginBundle/Integration/AbstractIntegration.php:838-863,2317-2345 @7.x] [code: app/bundles/PluginBundle/Command/FetchLeadsCommand.php:132-133 @7.x]
34. `plugin.leadpush` (campaign, form and point) iterates the selected published Integrations and calls `pushLead($lead, $config)`, then `pushLeadToCampaign()` when a campaign is chosen. Failures set `failed: 1, reason` in the campaign log metadata. [code: app/bundles/PluginBundle/EventListener/PushToIntegrationTrait.php:44-81 @7.x] [code: app/bundles/PluginBundle/EventListener/CampaignSubscriber.php:24-57 @7.x] [code: app/bundles/PluginBundle/EventListener/FormSubscriber.php:23-43 @7.x] [code: app/bundles/PluginBundle/EventListener/PointSubscriber.php:22-33 @7.x]
35. The action's Integration list offers only published Integrations supporting `push_lead`, grouped by plugin name. A published core (plugin-less) Integration with `push_lead` would fatal here; this is inferred, and none exists today. [code: app/bundles/PluginBundle/Form/Type/IntegrationsListType.php:24-133 @7.x]
36. `getMauticLead()` skips values equal to the translated "unknown", finds a Contact by unique identifiers, and saves with `LeadManipulator('plugin', <name>)` only when something changed. Exceptions are logged and `null` is returned. [code: app/bundles/PluginBundle/Integration/AbstractIntegration.php:1642-1777 @7.x]
37. `mautic:integration:fetchleads` (alias `mautic:integration:synccontacts`) has the options `-i` (required), `-d`/`--start-date`, `-t`/`--end-date`, `--fetch-all`, `-a`/`--time-interval` (default `15 minutes`), `-l`/`--limit` (default 100) and `-f`/`--force` (unused). [code: app/bundles/PluginBundle/Command/FetchLeadsCommand.php:33-94 @7.x]

With `push_leads` it calls `pushLeads()`, then `pushCompanies()` when `push_companies` is set. It otherwise always succeeds. [code: app/bundles/PluginBundle/Command/FetchLeadsCommand.php:106-284 @7.x]
39. `mautic:integration:pushleadactivity` (alias `mautic:integration:pushactivity`) calls `pushLeadActivity(['start','end'])` when defined. Salesforce and SugarCRM implement it. [code: app/bundles/PluginBundle/Command/PushLeadActivityCommand.php:13-91 @7.x] [code: plugins/MauticCrmBundle/Integration/CrmAbstractIntegration.php:168-171 @7.x]
40. Legacy and modern commands define `MAUTIC_AUDITLOG_USER` = Integration name, so audit-log entries are attributed to the Integration. [code: app/bundles/PluginBundle/Command/FetchLeadsCommand.php:112-113 @7.x] [code: app/bundles/IntegrationsBundle/Command/SyncCommand.php:110-113 @7.x]
41. With `-vv`, every legacy request and response is printed. Otherwise they go to the debug log with OAuth headers sanitised. [code: app/bundles/PluginBundle/EventListener/IntegrationSubscriber.php:31-113 @7.x]

## D. Legacy auth

43. OAuth2 login URL: `getAuthenticationUrl()?client_id&response_type=code&redirect_uri&state[&scope]`. The state is stored in session `<name>_csrf_token`, and a mismatch throws `mautic.integration.auth.invalid.state`. [code: app/bundles/PluginBundle/Integration/AbstractIntegration.php:994-1023,1077-1122 @7.x]
44. The legacy callback URL is public `/plugins/integrations/authcallback/{integration}`. `extractAuthKeys()` merges and encrypts keys when the token key is present, persists them, and stores the raw response in session. [code: app/bundles/PluginBundle/Config/config.php:6-47 @7.x] [code: app/bundles/PluginBundle/Integration/AbstractIntegration.php:1050-1065,1129-1175 @7.x] [docs: https://docs.mautic.org/en/7.2/plugins/zoho_crm.html#configure-the-zoho-crm-plugin]
45. OAuth1a callbacks sign with `oAuthHelper`, using `oauth_token` as the request token. [code: app/bundles/PluginBundle/Integration/AbstractIntegration.php:1105-1113,1282-1304 @7.x]
46. After the callback, the user lands on the authstatus page with a success or fail message. An unknown Integration yields `mautic.integration.notfound`. [code: app/bundles/PluginBundle/Controller/AuthController.php:19-94 @7.x]
47. `isAuthorized()` behaviour by type. `oauth1a`/`oauth2` need the token; an expired token with declared refresh keys triggers a refresh, and the result is whether the refresh succeeded. `key` checks `api_key`. `rest` checks the token key. `basic` needs username and password. Other types return true. [code: app/bundles/PluginBundle/Integration/AbstractIntegration.php:1207-1253 @7.x]
48. `makeRequest()` adds auth headers per type and has a default timeout of 10 s. It returns `['error' => [...]]` on a Guzzle `RequestException`, and `mautic.integration.missingkeys` when not configured. It parses the body as JSON, with `parse_str` as fallback. [code: app/bundles/PluginBundle/Integration/AbstractIntegration.php:580-589,657-833,878-986 @7.x]
49. SSO integrations (`sso_service`/`sso_form`) use callback `mautic_sso_login_check`. Their `extractAuthKeys()` does not persist keys, and they read `new_user_role` / `auto_create_user`. [code: app/bundles/PluginBundle/Integration/AbstractSsoServiceIntegration.php:34-104 @7.x]

## E. Sync engine: change tracking

50. Tracking skips anonymous Contacts and runs neither while `MAUTIC_INTEGRATION_SYNC_IN_PROGRESS` is defined nor when no published Integration has `sync` with that object mapped. [code: app/bundles/IntegrationsBundle/EventListener/LeadSubscriber.php:53-69,114-124 @7.x] [code: app/bundles/IntegrationsBundle/Helper/SyncIntegrationsHelper.php:93-131 @7.x]
51. Each tracked change replaces previous rows for that object and column. Owner → `owner_id`, points → `points`, DNC → `mautic_internal_dnc_<channel>` (value = reason), company change → `company`. Values are encoded as int, string, float, ISO-8601 datetime or `true`/`false`, and null becomes an empty string. `object_type` stores the entity FQCN. [code: app/bundles/IntegrationsBundle/EventListener/LeadSubscriber.php:71-97,147-197 @7.x] [code: app/bundles/IntegrationsBundle/Sync/VariableExpresser/VariableExpresserHelper.php:34-64 @7.x]
52. A listener on `INTEGRATION_BEFORE_CONTACT_FIELD_CHANGES` / `..._COMPANY_...` that throws `InvalidValueException` skips tracking for that Integration. [code: app/bundles/IntegrationsBundle/EventListener/LeadSubscriber.php:172-176,202-227 @7.x]
53. Deleting a Contact or Company removes its change-report and mapping rows; the listener runs at priority 255. [code: app/bundles/IntegrationsBundle/EventListener/LeadSubscriber.php:100-108,141-145 @7.x]
54. `mautic:integrations:cleanup` deletes change rows for Contacts that no longer exist, in batches of 1000 up to 100 000 per run. [code: app/bundles/IntegrationsBundle/Command/CleanupCommand.php:14-37 @7.x] [code: app/bundles/IntegrationsBundle/Entity/FieldChangeRepository.php:156-201 @7.x]

## F. Sync engine: execution

55. `mautic:integrations:sync <integration>` options: `-t`/`--start-datetime`, `--end-datetime` (UTC), `--mautic-object-id` (multi, `contact:12`/`company:3`), `--integration-object-id` (multi, `Account:12`), `-f`/`--first-time-sync`, `--disable-push`, `--disable-pull`, `--option key:value` (multi) and `--disable-activity-push`. [code: app/bundles/IntegrationsBundle/Command/SyncCommand.php:31-95 @7.x]
56. Invalid options return FAILURE. Any `Throwable` prints an error and returns FAILURE, and is rethrown in `dev`. Success prints the execution time. [code: app/bundles/IntegrationsBundle/Command/SyncCommand.php:101-126 @7.x]
57. `contact:N` is rewritten to `lead:N`. Datetimes are parsed as UTC, and an invalid one raises `InvalidValueException`. [code: app/bundles/IntegrationsBundle/Sync/DAO/Sync/InputOptionsDAO.php:52-200 @7.x]
58. Order: pull (if enabled), then push (if enabled), then `INTEGRATION_POST_EXECUTE`. With `--integration-object-id`, the pull stops after one iteration. [code: app/bundles/IntegrationsBundle/Sync/SyncProcess/SyncProcess.php:54-211,268-272 @7.x]
59. The per-object "from" date is `--start-datetime`, else the latest `last_sync_date` in `sync_object_mapping` for that Integration object (ignored if outside the window), else now minus 24 hours. The Mautic side always uses the explicit start or 24 hours. The "to" date is `--end-datetime` or the sync start time. [code: app/bundles/IntegrationsBundle/Sync/Helper/SyncDateHelper.php:30-114 @7.x]
60. Pull requests only fields whose direction is not `integration`-only, plus required fields. Objects are skipped when `--mautic-object-id` targets other object types. [code: app/bundles/IntegrationsBundle/Sync/SyncProcess/Direction/Integration/IntegrationSyncProcess.php:46-123 @7.x] [code: app/bundles/IntegrationsBundle/Sync/DAO/Mapping/MappingManualDAO.php:159-183 @7.x]
61. Matching: a `sync_object_mapping` row with `is_deleted=1` means the object is skipped. Otherwise a lookup by unique identifiers runs via `INTEGRATION_FIND_INTERNAL_RECORDS`, the first match wins, and a mapping row is created. [code: app/bundles/IntegrationsBundle/Sync/Helper/MappingHelper.php:40-115 @7.x]
62. "Required" covers Contact required plus unique-identifier fields, and Company required fields, regardless of Integration settings. An empty required value skips that field for an existing object and the whole object for a new one, with a notification. [code: app/bundles/IntegrationsBundle/Sync/SyncProcess/Direction/Internal/ObjectChangeGenerator.php:105-190,326-334 @7.x] [code: app/bundles/IntegrationsBundle/Sync/SyncDataExchange/Helper/FieldHelper.php:137-170 @7.x]
63. Required-but-empty coercion: email/date/datetime/boolean keep the original value, int becomes `0`, float becomes `1.0`, and other types raise `RequiredValueException`. [code: app/bundles/IntegrationsBundle/Sync/SyncProcess/Direction/Helper/ValueHelper.php:24-79 @7.x]
64. SyncJudge: identical values make Mautic win. **Hard** mode needs per-field certain dates on both sides. **Best** mode is hard, else both objects' possible change dates. **Fuzzy** mode is best, else one side's certain date newer than the other's possible date. Ties or missing dates leave the field unsynced. Mautic's certain date is the field-change `modified_at`. [code: app/bundles/IntegrationsBundle/Sync/SyncJudge/SyncJudge.php:22-36 @7.x] [code: app/bundles/IntegrationsBundle/Sync/SyncJudge/Modes/DateComparisonTrait.php:14-25 @7.x] [code: app/bundles/IntegrationsBundle/Sync/SyncProcess/Direction/Internal/ObjectChangeGenerator.php:192-280 @7.x]

Before that, `ReferenceResolver` turns a Contact `company` reference into the company name, and `FieldValidator` drops over-length or mistyped values with notifications. [code: app/bundles/IntegrationsBundle/Sync/SyncDataExchange/Internal/Executioner/OrderExecutioner.php:31-148 @7.x] [code: app/bundles/IntegrationsBundle/Sync/SyncDataExchange/Internal/Executioner/ReferenceResolver.php:27-95 @7.x]

Then `mautic_internal_dnc_<channel>` sets or removes DNC (0 removes it; an unknown reason means MANUAL), and `owner_id` sets the owner. Same-batch duplicates by unique identifier are reused. [code: app/bundles/IntegrationsBundle/Sync/SyncDataExchange/Internal/ObjectHelper/ContactObjectHelper.php:55-177,327-396 @7.x]

[code: app/bundles/IntegrationsBundle/Sync/SyncDataExchange/Internal/ReportBuilder/FullObjectReportBuilder.php:36-148 @7.x] [code: app/bundles/IntegrationsBundle/Sync/SyncDataExchange/Internal/ReportBuilder/PartialObjectReportBuilder.php:41-190 @7.x]
